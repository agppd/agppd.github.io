真正的程序往往远不止几十行，当代码量膨胀到数百、数千行时，如何组织代码就成了决定项目成败的关键。

C语言给出的答案是——**函数**。

函数不仅是代码复用的基本单位，更是**面向过程编程（Procedure-Oriented Programming）** 的核心载体。面向过程编程强调将解决问题的过程分解为若干清晰的步骤，并用函数封装每一个步骤，通过顺序、选择和循环结构来组织这些函数的调用，从而构建出完整的程序。

## 一、函数


### 1.1 函数定义与声明

```c
/* 函数定义：返回类型 函数名(形参列表) { 函数体 } */
int max(int a, int b) {
    return a > b ? a : b;
}

/* 函数声明（原型）：告知编译器函数的签名，常在头文件中出现 */
int max(int a, int b);   /* 或 int max(int, int); */
```

**关键点**：
- 函数在使用前必须被声明或定义，否则编译器会隐式声明（返回int，参数不定）。
- 如果函数没有返回值，使用 `void`。
- 如果函数不接受参数，应写 `void func(void)`，而非 `func()`。

### 1.2 参数传递：值传递是唯一方式

C语言中所有参数都是**传值**的。这意味着函数内部对形参的修改不会影响实参。

```c
void swap_bad(int a, int b) {
    int tmp = a; a = b; b = tmp;  /* 只交换了副本 */
}

int x = 1, y = 2;
swap_bad(x, y);  /* x 和 y 不变 */
```

若想修改实参，必须传递地址：

```c
void swap_good(int *a, int *b) {
    int tmp = *a; *a = *b; *b = tmp;
}
swap_good(&x, &y);  /* 现在 x=2, y=1 */
```

### 1.3 返回值

返回值可以是基本类型、指针、结构体。

## 二、面向过程编程的本质——顺序执行

**面向过程编程（POP）** 的核心思想可以概括为四个字：**按部就班**。它只关注业务流程的时序逻辑，即完成一件事需要哪几个步骤，以及这些步骤的先后顺序。

### 2.1 最原始的编程思维：顺序结构

这是编程中最直接的思维方式，等同于程序中的“顺序结构”——代码从上到下、逐条执行，机械地罗列待完成的事件。

例如，描述一个人早晨上班的过程：

```c
/* 纯顺序执行，没有函数封装 */
int main(void) {
    /* 步骤1：起床 */
    int is_awake = 1;
    /* 步骤2：洗漱 */
    int is_clean = 1;
    /* 步骤3：吃早餐 */
    int is_full = 1;
    /* 步骤4：出门上班 */
    int is_at_work = 1;
    return 0;
}
```

在这个阶段，**数据和操作完全分离**。变量（如 `is_awake`）仅仅是存储状态的容器，而操作（如赋值）直接写在主流程中。代码就像一张待办清单，按顺序罗列所有动作。

### 2.2 特点：简单直观，但缺乏抽象

- **时序驱动**：程序的执行流完全由步骤的物理顺序决定。
- **无封装性**：每一步的具体实现都暴露在主流程中，读者一眼就能看到所有细节。
- **数据裸露**：状态变量散落在各处，修改任何步骤都可能影响后续变量的值。

这种写法对于极其简单的任务（如计算器）尚可，但一旦业务发生变化，就会暴露出严重的**局限性**。
