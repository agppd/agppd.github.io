## 1. 单继承（Single Inheritance）

**定义**：一个派生类（子类）仅从一个基类（父类）继承。

### 1.1 内存布局（C 语言等价模型）
在 C 语言中，单继承等价于**将基类对象作为派生类结构体的第一个成员**。

```c
// C 语言模拟单继承
struct Base { int base_data; };
struct Derived { 
    struct Base base;  // 必须放在第一个位置，保证首地址一致
    int derived_data; 
};
```

**C++ 实际内存布局**：
```cpp
class Base {
    int base_data;
};
class Derived : public Base {
    int derived_data;
};
// sizeof(Derived) == sizeof(Base) + sizeof(int) （不考虑对齐填充）
```
**关键规律**：基类子对象位于派生类对象的**起始位置**（偏移量为 0），因此**基类指针**可以安全地指向派生类对象，且无需调整指针偏移量（`static_cast` 效率极高）。

### 1.2 构造与析构顺序
- **构造顺序**：先构造基类，再构造派生类成员变量，最后执行派生类构造函数体。
- **析构顺序**：先执行派生类析构函数体，再销毁派生类成员，最后调用基类析构函数（**与构造完全相反**）。

```cpp
class Base {
public:
    Base() { cout << "Base ctor" << endl; }
    ~Base() { cout << "Base dtor" << endl; }
};
class Derived : public Base {
public:
    Derived() { cout << "Derived ctor" << endl; }
    ~Derived() { cout << "Derived dtor" << endl; }
};
// 实例化 Derived d; 输出顺序：
// Base ctor -> Derived ctor -> Derived dtor -> Base dtor
```

## 2. 多重继承（Multiple Inheritance）（俗称“双继承”）

**定义**：一个派生类同时从**两个或多个**基类继承。

### 2.1 内存布局（C 语言等价模型）
在 C 中，多重继承相当于在结构体中**依次排列多个基类子对象**。

```c
struct Base1 { int b1; };
struct Base2 { int b2; };
struct Derived { 
    struct Base1 base1; // 偏移量 0
    struct Base2 base2; // 偏移量 sizeof(Base1)
    int derived_data; 
};
```

**C++ 内存布局关键点**：
- 派生类对象包含所有基类子对象，按**声明顺序**排列（`class Derived : public Base1, public Base2`）。
- 指向**第一个基类**（Base1）的指针与指向派生类对象的指针，**内存地址相同**（无需调整）。
- 指向**第二个基类**（Base2）的指针，若指向派生类对象，编译器会在底层**自动进行偏移量调整**（`this` 指针偏移）。

### 2.2 名称冲突与二义性（作用域解析）
当两个基类拥有同名成员（函数或变量）时，派生类直接访问会产生**二义性编译错误**，必须使用**作用域解析运算符 `::`** 显式指明。

```cpp
class Base1 { public: void func() { cout << "Base1"; } };
class Base2 { public: void func() { cout << "Base2"; } };
class Derived : public Base1, public Base2 {};

int main() {
    Derived d;
    // d.func();   // 错误！ambiguous（二义性）
    d.Base1::func(); // 输出 Base1
    d.Base2::func(); // 输出 Base2
}
```

### 2.3 对象切片与指针转换（编译器自动调整指针）
```cpp
Derived d;
Base2* p2 = &d;  // 编译器隐式执行: Base2* p2 = (Base2*)((char*)&d + offset_of_Base2);
```
这种偏移量调整是 C 语言中不存在的自动化操作，理解这一点对后期使用 `dynamic_cast` 至关重要。

## 3. 菱形继承（Diamond Inheritance）——问题的根源

**定义**：当多个中间基类继承自同一个顶级基类，而最终派生类又同时继承这些中间基类时，继承体系呈菱形结构。

```
      Base
     /    \
  Base1   Base2
     \    /
    Derived
```

### 3.1 引发的问题（数据冗余 + 二义性）

```cpp
class Base { public: int data; };
class Base1 : public Base {};
class Base2 : public Base {};
class Derived : public Base1, public Base2 {};

int main() {
    Derived d;
    // d.data = 10;   // 错误！ambiguous：到底是 Base1::data 还是 Base2::data？
    
    // 必须指定路径
    d.Base1::data = 10;
    d.Base2::data = 20;
    
    // 内存中，Derived 内部包含两份独立的 Base 子对象！
    cout << sizeof(Derived); // 至少包含 2 * sizeof(Base) + 对齐
}
```

### 3.2 内存布局（菱形导致重复）
此时 `Derived` 对象内部含有：
- `Base1` 子对象（内含一份 `Base` 子对象）
- `Base2` 子对象（内含另一份独立的 `Base` 子对象）
这不仅浪费内存，更严重的是，如果你希望通过 `Base*` 指向 `Derived`，编译器将不知道指向哪一份拷贝。

## 4. 虚继承（Virtual Inheritance）——菱形问题的救星

**定义**：在继承时使用 `virtual` 关键字（如 `class Base1 : virtual public Base`），告诉编译器**共享同一个顶级基类子对象**。

### 4.1 语法修正
```cpp
class Base { public: int data; };
class Base1 : virtual public Base {};  // 虚继承
class Base2 : virtual public Base {};  // 虚继承
class Derived : public Base1, public Base2 {};

int main() {
    Derived d;
    d.data = 100;  // 现在没有二义性！因为只有一份 Base
    // 此时 sizeof(Derived) 大于 sizeof(Base1)+sizeof(Base2)+sizeof(Base)
    // 因为编译器插入了额外的偏移量指针（vbptr，虚基类指针）
}
```

### 4.2 底层实现机制（VBTable 与 VBPtr）
为了在运行时找到那份共享的 `Base` 子对象，编译器引入了类似于虚函数（VTable）的机制：

- **虚基类指针（VBptr）**：每个派生类对象中会隐含一个或多个指针，指向**虚基类表（VBTable）**。
- **虚基类表（VBTable）**：存储该对象中各个虚基类子对象相对于当前对象起始地址的**偏移量**。
- **动态调整**：由于 `Base` 的位置在派生类中可能被放在对象末尾，编译器通过 VBptr 运行时计算偏移量来访问 `data`。

**C 语言的逻辑类比**：
```c
// C 模拟虚继承：存储偏移量，运行时计算地址
struct Derived {
    void* vbptr;      // 指向偏移量表
    int base1_data;
    int base2_data;
    // Base 子对象不一定在开头，根据偏移量动态获取
};
```

### 4.3 极其重要的构造顺序（客观强制规则）
当使用虚继承时，**虚基类的构造函数由最终派生类（Most Derived Class）直接调用**，而不是由中间基类调用。这保证了虚基类在整个继承树中只被初始化一次。

**构造顺序优先级**（从上到下，绝对严格）：
1.  **虚基类**（按它们在继承体系中**深度优先**从左到右出现顺序，且在最终派生类构造之前）。
2.  **非虚基类**（按声明顺序）。
3.  **成员对象**。
4.  **派生类构造函数体**。

```cpp
class Base { public: Base(int x) { cout << "Base "; } };
class Base1 : virtual public Base { public: Base1() : Base(1) { cout << "Base1 "; } };
class Base2 : virtual public Base { public: Base2() : Base(2) { cout << "Base2 "; } };
class Derived : public Base1, public Base2 {
public:
    // 注意：初始化列表中直接调用 Base(3)，绕过 Base1/Base2 的 Base 构造
    Derived() : Base(3), Base1(), Base2() { cout << "Derived"; }
};
// 实例化 Derived d; 输出：Base Base1 Base2 Derived（Base 只构造一次，且用 3 而不是 1 或 2）
```
**客观陷阱**：中间基类（Base1/Base2）的构造函数中如果调用了虚基类的方法，此时虚基类尚未构造完成（因为最终派生类还没开始构造），这会导致**未定义行为**。因此，**永远不要在构造函数中调用虚函数**。

## 5. 三种继承形态的客观对比表

| 特性 | 单继承 | 多重继承（非菱形） | 菱形继承（普通） | 菱形继承（虚继承） |
|------|--------|-------------------|----------------|-------------------|
| 基类子对象个数 | 1 份 | N 份（N为基类数） | 顶级基类 2 份 | 顶级基类 1 份（共享） |
| 内存开销 | 最小 | 正常 | 数据冗余，内存浪费 | 额外存储 VBPtr 和偏移量表 |
| 成员访问二义性 | 无 | 需 `::` 手动分辨 | 严重二义性，强制 `::` | 无二义性，直接访问 |
| 基类指针转换 | 无偏移 | 非首基类需偏移调整 | 无法直接转顶级基类（会歧义） | 可安全转换，编译器自动查表 |
| 构造复杂度 | 简单线性 | 按声明顺序 | 顶级基类被构造两次 | 最终派生类直接构造虚基类（复杂） |
| 适用场景 | 绝大多数设计 | 接口分离（纯抽象类） | **强烈不推荐**（除非遗留代码） | 解决菱形问题（如 iostream 继承体系） |

## 6. 针对 C 程序员的建议与客观限制

1.  **优先使用组合而非继承**：C 语言的结构体嵌套（组合）比继承更加直观且耦合度低。C++ 的继承主要用于**接口实现**和**运行时多态**。
2.  **多重继承的真实用途**：在实际工程中，多重继承通常仅用于继承多个**纯虚接口类**（只有纯虚函数，没有数据成员），这不会导致内存布局复杂化（接口类无数据成员，即便菱形继承也无数据冗余风险）。
3.  **虚继承的性能代价**：每次访问虚基类的成员变量，都涉及**间接寻址**（通过 VBPtr 和偏移量表），相比普通成员访问（直接地址偏移），性能略低且无法内联优化。
4.  **绝对不要跨 DLL 边界使用虚继承**：不同编译器（甚至同一编译器的不同版本）对 VBTable 的布局实现细节不同，极易导致内存访问崩溃。

## 7. 完整运行代码（验证构造顺序与大小）

```cpp
#include <iostream>
using namespace std;

class Grand {
public:
    int g;
    Grand(int v = 0) : g(v) { cout << "Grand(" << v << ") "; }
};

class Mother : virtual public Grand {
public:
    Mother() : Grand(1) { cout << "Mother "; }
};

class Father : virtual public Grand {
public:
    Father() : Grand(2) { cout << "Father "; }
};

class Child : public Mother, public Father {
public:
    // 必须直接初始化 Grand，否则 Grand 会被默认构造
    Child() : Grand(999), Mother(), Father() { cout << "Child "; }
};

int main() {
    Child c;
    cout << endl;
    cout << "sizeof(Grand)=" << sizeof(Grand) << endl;
    cout << "sizeof(Child)=" << sizeof(Child) << endl; 
    // 输出结果验证：Grand 只构造一次，且值为 999
    // 输出: Grand(999) Mother Father Child
    return 0;
}
```
