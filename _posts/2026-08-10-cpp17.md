## 1. C++ 的四种类型转换（Type Casting）

ANSI C 使用统一的 `(新类型)表达式` 或 `新类型(表达式)` 进行强制类型转换，这种转换“一把抓”不区分场景，在 C++ 中容易误用且难以搜索。C++ 引入了四种具名转换运算符，明确各自的用途和约束。

### 1.1 `static_cast`（编译期安全转换）
**用途**：进行“有明确语义”的转换，编译时检查合法性。
- 基本数据类型互转（`int` ↔ `double`）。
- 基类与派生类之间**向上转型（Upcast）**（将派生类指针/引用转为基类，安全且无需运行时开销）。
- 基类与派生类之间**向下转型（Downcast）**（无运行时检查，需要程序员保证类型正确性）。

```cpp
class Base {};
class Derived : public Base {};

int main() {
    // 基本类型转换
    double pi = 3.14159;
    int val = static_cast<int>(pi);   // 截断为 3

    // 向上转型（安全，隐含转换也可，但显式更清晰）
    Derived d;
    Base* b = static_cast<Base*>(&d); // 偏移量为 0 或向上调整

    // 向下转型（不安全，若实际指向非 Derived 则 UB）
    Base* b2 = new Derived();
    Derived* d2 = static_cast<Derived*>(b2); // 程序员保证 b2 实际指向 Derived

    // 错误用法：无法转换不相关类型
    // int* p = static_cast<int*>(b2); // 编译错误！
}
```
**对 C 程序员的提示**：`static_cast` 对应于 C 中最常见的“安全”强制转换，但它不会去除 `const`，也不会进行危险的位重解释。

---

### 1.2 `dynamic_cast`（运行时安全转换）
**用途**：在继承体系中**安全地向下转型（Downcast）或跨转型（Cross-cast）**，依赖运行时类型信息（RTTI），转型失败时有明确反馈。
- 要求基类至少含有一个虚函数（才有 VTable，用于存储 RTTI）。
- 若转换失败，**指针版本返回 `nullptr`**，**引用版本抛出 `std::bad_cast`**。

```cpp
class Animal { public: virtual ~Animal() {} }; // 有虚函数
class Dog : public Animal {};
class Cat : public Animal {};

void test(Animal* a) {
    // 向下转型：运行时检查 a 是否真的指向 Dog
    Dog* d = dynamic_cast<Dog*>(a);
    if (d) {
        cout << "It's a Dog!" << endl;
    } else {
        cout << "Not a Dog." << endl;
    }
}

int main() {
    Animal* a1 = new Dog();
    Animal* a2 = new Cat();
    test(a1); // 输出: It's a Dog!
    test(a2); // 输出: Not a Dog.
    delete a1; delete a2;
}
```
**客观限制**：`dynamic_cast` 有运行时开销（查 VTable），非多态类型（无虚函数）不能使用。

---

### 1.3 `const_cast`（去除/添加常量性）
**用途**：专门用于移除（或添加）变量的 `const` / `volatile` 限定符。这是唯一能处理常量性的转换。
- 主要场景：调用一个**不修改参数**但声明时**未加 `const`** 的老旧 C 函数。

```cpp
void legacy_c_function(char* str) { // C 库函数，声明没加 const
    printf("%s\n", str);
}

int main() {
    const char* msg = "Hello";
    // legacy_c_function(msg); // 错误！const char* 不能隐式转 char*

    // 正确做法：明确告知编译器去 const，前提是函数确实不会修改
    legacy_c_function(const_cast<char*>(msg));
}
```
**严重警告**：若被转换的对象本质上是 `const`（如定义在只读内存段），试图通过转换后的指针修改其内容会导致**未定义行为**。`const_cast` 仅用于修补接口缺陷，而非篡改逻辑常量。

---

### 1.4 `reinterpret_cast`（位模式重解释）
**用途**：进行**低级、危险的位模式重解释**，相当于 C 语言中最强制转换（原样搬运二进制位）。
- 将指针转为整数，或将整数转为指针。
- 在不同类型的指针之间进行转换（如 `int*` 转 `char*`，用于查看内存字节）。
- 几乎没有编译时检查或运行时检查，全凭程序员保证合法性。

```cpp
int main() {
    int x = 0x12345678;
    // 将 int 指针视为 char 指针，逐字节查看内存（大小端相关）
    char* bytes = reinterpret_cast<char*>(&x);
    for (int i = 0; i < 4; ++i) {
        printf("%02x ", bytes[i]);
    }

    // 将整数存回指针（极危险，通常用于底层硬件编程或嵌入式）
    uintptr_t addr = 0x1000;
    volatile int* reg = reinterpret_cast<int*>(addr);
    // *reg = 10; // 写入特定内存地址
    return 0;
}
```
**客观建议**：除了底层系统编程或序列化，应尽量避免使用 `reinterpret_cast`，它完全绕过了 C++ 的类型系统。

### 1.5 四种转换与 C 风格转换的对比总结

| 特性 | C 风格 `(T)` | `static_cast` | `dynamic_cast` | `const_cast` | `reinterpret_cast` |
|------|-------------|---------------|----------------|--------------|---------------------|
| 基本类型转换 | 可以 | 可以 | 不可以 | 不可以 | 不可以 |
| 继承体系向上转型 | 可以（隐含） | 可以 | 可以（冗余） | 不可以 | 不可以 |
| 继承体系向下转型 | 可以（无检查） | 可以（无检查） | 可以（运行时检查） | 不可以 | 不可以 |
| 去除 const | 可以 | 不可以 | 不可以 | 可以 | 不可以 |
| 指针↔整数 | 可以 | 不可以 | 不可以 | 不可以 | 可以 |
| 安全性 | 最低 | 编译期安全 | 运行时安全 | 受限安全 | 极低 |

## 2. 智能指针（Smart Pointers）

在 C 语言中，动态内存管理依靠 `malloc` / `calloc` 和 `free`，需要程序员在每一个退出分支上手动释放，极易遗漏。C++ 的智能指针（头文件 `<memory>`）将**动态对象的生命周期绑定到栈对象**，利用 RAII 自动释放资源。

### 2.1 `std::unique_ptr`（独占所有权）
**特性**：
- 同一时刻**只有一个** `unique_ptr` 指向某个对象。
- **不可拷贝**（拷贝构造函数和赋值运算符被删除），但**可以移动**（`std::move`）。
- 指针销毁时（离开作用域或重置），自动 `delete` 所管理的对象。
- 相较于原始指针，零额外开销（尺寸与原始指针相同）。

```cpp
#include <memory>
#include <iostream>
using namespace std;

class Resource {
public:
    Resource() { cout << "Resource acquired\n"; }
    ~Resource() { cout << "Resource released\n"; }
    void work() { cout << "Working...\n"; }
};

int main() {
    // 创建 unique_ptr（推荐使用 make_unique，C++14 起）
    unique_ptr<Resource> ptr1 = make_unique<Resource>();
    ptr1->work();

    // ptr2 = ptr1; // 错误！不可拷贝
    unique_ptr<Resource> ptr2 = move(ptr1); // 转移所有权，ptr1 变为空

    if (!ptr1) cout << "ptr1 is null\n";
    ptr2->work();

    // 离开作用域，Resource 自动析构
    return 0;
}
// 输出顺序：Resource acquired -> Working... -> ptr1 is null -> Working... -> Resource released
```

**使用场景**：工厂函数返回值、容器中存放指针（需配合移动语义）、作用域内独占资源。

---

### 2.2 `std::shared_ptr`（共享所有权）
**特性**：
- 允许多个 `shared_ptr` **共享**同一个对象。
- 内部维护**引用计数**（控制块），当最后一个 `shared_ptr` 销毁时，自动释放对象。
- 拷贝/赋值时引用计数原子递增（线程安全），析构时递减。
- 存在一定额外开销（控制块分配、原子操作）。

```cpp
#include <memory>
#include <iostream>
using namespace std;

class Node {
public:
    int value;
    explicit Node(int v) : value(v) { cout << "Node " << value << " created\n"; }
    ~Node() { cout << "Node " << value << " destroyed\n"; }
};

int main() {
    shared_ptr<Node> sp1 = make_shared<Node>(10); // 引用计数: 1
    {
        shared_ptr<Node> sp2 = sp1;               // 拷贝，引用计数: 2
        cout << "Use count: " << sp1.use_count() << endl; // 输出 2
    } // sp2 析构，引用计数: 1
    cout << "Use count: " << sp1.use_count() << endl; // 输出 1
    // 离开主作用域，sp1 析构，引用计数归零，Node 释放
    return 0;
}
```

**使用场景**：多个对象需要共享同一份数据（如缓存、图结构中的节点），或不确定资源生命周期。

---

### 2.3 `std::weak_ptr`（弱引用，打破循环引用）
**特性**：
- 指向 `shared_ptr` 管理的对象，但**不增加引用计数**。
- 不能直接解引用，需要先调用 `lock()` 获得一个临时的 `shared_ptr`（若对象存活则返回有效，否则为空）。
- 主要用于解决 **循环引用** 导致的内存泄漏（例如双向链表或父子互相持有 `shared_ptr`）。

```cpp
#include <memory>
#include <iostream>
using namespace std;

struct B; // 前向声明

struct A {
    shared_ptr<B> b_ptr;
    ~A() { cout << "A destroyed\n"; }
};

struct B {
    weak_ptr<A> a_ptr; // 使用 weak_ptr 打破循环
    ~B() { cout << "B destroyed\n"; }
};

int main() {
    shared_ptr<A> a = make_shared<A>();
    shared_ptr<B> b = make_shared<B>();
    a->b_ptr = b;       // A 持有 B 的 shared_ptr
    b->a_ptr = a;       // B 持有 A 的 weak_ptr（不增加引用计数）
    // 离开作用域时，a 和 b 都能正确释放
    return 0;
}
// 输出: B destroyed, A destroyed（顺序取决于析构次序，但均释放）
```

**使用场景**：缓存中的过期检测、观察者模式、需要避免循环引用的任何共享所有权场景。

### 2.4 智能指针与 C 代码互操作

- **获取原始指针**：`ptr.get()` 获得裸指针，仅用于调用不接受智能指针的 C 函数，**严禁**用 `delete` 释放。
- **自定义删除器**：智能指针支持传入自定义删除器，可适配 `FILE*`、`malloc/free` 等 C 资源。
```cpp
#include <memory>
#include <cstdio>
using namespace std;

// 管理 FILE* 的智能指针
unique_ptr<FILE, decltype(&fclose)> filePtr(fopen("test.txt", "r"), &fclose);
if (filePtr) {
    fread(buffer, 1, size, filePtr.get());
} // 离开作用域自动 fclose
```

## 3. 命名空间（Namespace）

ANSI C 中，所有全局符号（函数、全局变量、类型）都在一个**全局命名空间**，大型项目中极易命名冲突。常见的 C 解决方案是加前缀（如 `myLib_open`、`myLib_read`），既繁琐也无法完全隔离。C++ 的 `namespace` 提供了逻辑分组和名称隔离机制。

### 3.1 定义与使用
```cpp
// 定义命名空间
namespace Math {
    const double PI = 3.14159;
    double square(double x) { return x * x; }
}

namespace FileIO {
    void open(const char* path) { /* ... */ }
    void close() { /* ... */ }
}

int main() {
    // 使用作用域解析运算符 ::
    double area = Math::PI * Math::square(5.0);
    FileIO::open("data.txt");
    // FileIO::close();
    return 0;
}
```

### 3.2 `using` 声明与指令
- **`using 声明`**：将某个特定符号引入当前作用域（如 `using Math::PI;`）。
- **`using 指令`**：将整个命名空间的符号全部引入当前作用域（如 `using namespace Math;`）。**谨慎使用**（通常仅在局部作用域或 .cpp 文件中，避免污染全局）。

```cpp
#include <iostream>
using namespace std; // 将 std 所有符号引入（教学示例常用，工程中推荐细化）

int main() {
    // 只引入 cout 和 endl，避免全部展开
    using std::cout;
    using std::endl;
    cout << "Hello" << endl;
    return 0;
}
```

### 3.3 命名空间别名
适用于深层嵌套或长命名空间。
```cpp
namespace VeryLongNamespaceName {
    void func() {}
}
namespace Short = VeryLongNamespaceName;
Short::func();
```

### 3.4 匿名命名空间（替代 C 的 `static`）
在 C 语言中，用 `static` 关键字修饰全局函数/变量使其仅在当前文件可见（内部链接）。C++ 推荐使用**匿名命名空间**实现这一效果，且对类型（类/结构体）也有效。

```cpp
// file.cpp 中
namespace {
    // 仅在当前编译单元可见，等价于 static
    int internal_counter = 0;
    void helper_function() { /* ... */ }
    struct InternalType { /* ... */ };
}

// 外部文件无法访问 internal_counter、helper_function 或 InternalType
```
**客观优势**：匿名命名空间的符号具有外部链接（但名字被编译器修饰为唯一不可见名称），可与模板配合使用；而 C 的 `static` 是内部链接。在 C++ 工程中，匿名命名空间是**文件作用域私有符号**的推荐写法。

### 3.5 标准库命名空间 `std`
C++ 标准库的所有名称（容器、算法、IO 流、智能指针、异常等）都定义在命名空间 `std` 中。避免在头文件中使用 `using namespace std;`，以免污染全局命名空间；在 .cpp 源文件中可酌情使用。

```cpp
#include <vector>
#include <string>

// .cpp 文件中可局部展开
using namespace std;

void foo() {
    vector<string> v;
    v.push_back("hello");
}
```

## 4. 三者的综合协同

By DS

这三个特性在实际 C++ 项目中通常协同使用：

1. **`static_cast` / `dynamic_cast`** 结合智能指针：
   ```cpp
   shared_ptr<Animal> a = make_shared<Dog>();
   shared_ptr<Dog> d = dynamic_pointer_cast<Dog>(a); // STL 提供的智能指针特化转换
   ```

2. **命名空间** 包裹自定义类型和智能指针别名：
   ```cpp
   namespace MyLib {
       using Ptr = std::unique_ptr<MyClass>;
       class MyClass { /* ... */ };
   }
   ```

3. **异常与智能指针**共同构建 RAII：智能指针的析构在栈展开时必然执行，确保异常发生时资源依然被释放（已在前文异常讲解中体现）。
