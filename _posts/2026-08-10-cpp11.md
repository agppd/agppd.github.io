## 1. 基础词法与表达式

### 共性
- 关键字（`int`、`char`、`void`、`struct`、`union`、`enum`、`typedef`、`const`、`volatile`、`static`、`extern` 等）保持一致。
- 运算符及其优先级、结合性完全相同。
- 数字字面量（八进制、十六进制、后缀 `U`/`L`/`LL`）用法一致。

### 客观差异
- **字符字面量类型**：  
  - C 标准：`'A'` 类型为 `int`。  
  - C++ 标准：`'A'` 类型为 `char`。  
  因此 `sizeof('A')` 在 C 中通常为 4（取决于 `int` 大小），在 C++ 中恒为 1。

```c
#include <stdio.h>
void test_char_size() {
    printf("sizeof('A') = %zu\n", sizeof('A'));
    // C 输出 4（常见），C++ 输出 1
}
```

- **字符串字面量类型**：  
  - C 中为 `char[N]`，C++ 中为 `const char[N]`。  
  在 C++ 中将字符串字面量赋给 `char*`（非 `const`）会被标记为弃用，通常编译器会发出警告或错误。

## 2. 控制流程与语句

`if-else`、`for`、`while`、`do-while`、`switch-case`、`break`、`continue`、`goto`、`return` 的语法和执行逻辑在两种语言中完全一致。

**仅一点细微差异**：  
- C++ 在 `for` 循环初始化部分允许声明多个同类型变量（如 `for(int i=0, j=0; ...)`），C99 同样支持，但 C89 不支持。若环境仅支持 C89，此为差异点。

---

## 3. 指针、数组与内存寻址

### 共享规则
- 数组名退化为指针。
- 指针算术运算基于所指类型的大小。
- `NULL` 宏保留（C++11 起推荐 `nullptr`，但 `NULL` 仍然可用）。

### 强制差异（导致 C 代码无法在 C++ 下编译）
- **`void*` 隐式转换禁止**：C 允许 `void*` 隐式转换为任意对象指针类型；C++ 必须显式强制转换。

```c
#include <stdlib.h>
void test_void_ptr() {
    void *vptr = malloc(10 * sizeof(int));

    // C 合法，C++ 报错（invalid conversion）
    int *ptr1 = vptr;   

    // C 与 C++ 均通过（显式 C 风格转换）
    int *ptr2 = (int*)vptr; 

    // C++ 推荐写法（static_cast），C 不识别
    // int *ptr3 = static_cast<int*>(vptr); // 仅限 C++
}
```

## 4. 结构体、联合体与枚举

### 结构体/联合体类型名使用
- **C**：`struct` 标签独立命名空间，使用时必须加 `struct`（除非 `typedef`）。  
- **C++**：标签自动注入普通命名空间，可直接使用类型名（亦可保留 `struct` 关键字）。

```c
struct Point { int x; int y; };

void test_struct() {
    struct Point p1; // C 和 C++ 均通过
    Point p2;        // C 报错（unknown type），C++ 通过
}
```

### 枚举与整数的隐式转换
- **C**：允许将整数值隐式赋给枚举变量。  
- **C++**：禁止，必须显式强制转换。

```c
enum Color { RED = 0, GREEN = 1 };

void test_enum() {
    enum Color c;
    c = 1;                // C 合法，C++ 报错
    c = (enum Color)1;    // 均通过
}
```

## 5. 函数声明与定义

### 共性
- 返回值类型、参数列表语法一致。
- `static inline` 在两种语言中均支持。

### 强制差异（导致 C 代码无法编译）
- **函数原型必须前置**：  
  C（C90）允许隐式声明（假定返回 `int`）；C++ 完全禁止，必须在调用前提供原型或定义。

```c
// 未提供声明
void test_implicit() {
    int r = add(3, 4); // C90 可编译（警告），C++ 报错
}
int add(int a, int b) { return a + b; }
```

- **空参数列表语义不同**：  
  - `void f();` 在 C 中表示“参数类型未指定”，在 C++ 中表示“无参数”。  
  - 两种语言均将 `void f(void)` 明确解释为“无参数”。

## 6. 预处理指令

`#include`、`#define`、`#ifdef`、`#ifndef`、`#undef`、`#error`、`#line`、`#pragma` 的语法和求值逻辑完全一致，无差异。

---

## 7. 标准库头文件与标识符

- C 标准库头文件（如 `<stdio.h>`、`<stdlib.h>`、`<string.h>`、`<math.h>`、`<ctype.h>`、`<time.h>`）在 C++ 中仍可使用，对应函数（`printf`、`malloc`、`strcpy` 等）和宏的用法保持不变。
- C++ 提供了对应的 `<cstdio>`、`<cstdlib>` 等头文件，其中符号被放入 `std` 命名空间，但为兼容性，大多数实现也在全局命名空间中声明它们，因此直接调用 `printf` 仍有效。

---

## 8. 链接性与作用域差异

| 特性 | ANSI C | C++ |
|------|--------|-----|
| 顶层 `const` 变量默认链接性 | 外部链接 | 内部链接（需 `extern` 显式声明以恢复外部链接） |
| `static` 全局变量/函数 | 内部链接 | 内部链接（一致） |
| 枚举常量作用域 | 所在作用域可见 | 一致 |
| 结构体成员访问 | 通过 `.` / `->` | 一致 |

```c
// 文件 a.c / a.cpp
const int global_const = 100; 
// C 中默认外部链接，其他文件可 extern 引用
// C++ 中默认内部链接，若需外部链接必须写：
// extern const int global_const = 100;
```

## 9. C 语法特性在 C++ 中不可用（编译错误）

以下 C 语言特性被 C++ 标准明确排除，无法编译：

- **K&R 风格函数定义**（参数类型在括号后声明）
- **可变长度数组（VLA）**
- **指定初始化器**（如 `{ .x = 1 }`，C++20 虽引入部分聚合初始化，但语法和语义不同）
- **复合字面量**（如 `(int[]){1,2,3}`）
- **`restrict` 关键字**（但部分编译器提供 `__restrict` 扩展）

```c
// 以下代码在 C++ 中均报错

// 1. K&R 定义
int old_style(a, b) int a; int b; { return a + b; }

// 2. VLA
void vla(int n) { int arr[n]; }

// 3. 指定初始化器
struct Data { int x; int y; };
void des_init() { struct Data d = { .x = 1, .y = 2 }; }

// 4. 复合字面量
void comp_lit() { int *p = (int[]){1, 2, 3}; }
```

## 10. 迁移验证建议

将现有 C 代码重命名为 `.cpp` 文件，并使用 C++ 编译器编译，可快速定位上述不兼容点。

### 常用编译命令（Linux / macOS）
```bash
# C 编译（以 C99 为例）
gcc -std=c99 -Wall test.c -o test_c

# C++ 编译（以 C++11 为例）
g++ -std=c++11 -Wall test.cpp -o test_cpp
```

推荐在 C++ 编译时**禁用宽松模式**（如 GCC 的 `-fpermissive`），以便暴露所有标准层面的错误，确保代码严格符合 C++ 标准。

---

## 总结

- C++ 保留了 C 的绝大多数基础语法（控制流、指针运算、数组、结构体成员访问）和标准库接口。
- 迁移时主要需修正的差异集中在 **类型安全性**（`void*`、枚举转换）、**声明严格性**（函数原型、空参数列表）和 **链接性规则**（`const` 全局变量）。
- 部分 C99 特性（VLA、指定初始化器等）在 C++ 中无标准支持，需改用其他实现方式（如 `std::vector`、构造函数等，但超出本文范围）。
